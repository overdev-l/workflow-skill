# 全页面极简风格审查

日期：2026-09-15。代码基线：`19d1cfb`。本轮交付为审查与修复建议，未实施下述产品修改。

## 结论

当前没有达到极简目标。主要问题是同一信息多次表达、相同动作重复出现、容器层级过多、固定高度制造无效留白，以及成功/正常状态持续抢占注意力。此前统一色板、尺寸和三栏骨架不足以解决这些信息组织问题。

保留已经有效的设计：业务三栏、账号与设置双栏；账号工具 Tab + 卡片网格及“刷新全部 / 添加账号”；全宽规则编辑；无输入 outline/焦点环；隐藏滚动条并保留滚动能力。此次建议不更换配色、不取消功能、不用隐藏真实错误或授权提示换取表面简洁。

## 证据与覆盖

- 本轮新实机观察：1020×680 深色窗口，业务 Master 311px；本地 Skill、远程 Skill、工作流图、步骤编辑、Skill 预览、捕获空态、全局 AI 环境、Codex 有配额账号页。
- 尝试进入项目环境后，Computer Use 连续返回 `timeoutReached`；重置会话、重新连接仍超时。因此项目环境、MCP、规则、设置四页、弹窗和独立窗口本轮以当前源码检查为主，不能标记为新实机验收通过。前序截图只提供背景，不作为本轮新截图。
- 无产品代码修改，无真实账号切换、系统授权、注入、迁移、安装或删除。未改变主题与持久化列宽。源码覆盖下表所有页面/视图，未穷举全部运行时状态。
- 使用 impeccable 的产品设计准则进行人工顺序审查，先完成设计判断再运行静态检测；没有进行独立双 Agent 评分或注入可视化覆盖层。

## 优先整改

### P1：工作流重复操作和数量

`apps/desktop/src/App.tsx:3139` 起：顶层保存修改、保存为 Skill、导出代码；步骤编辑内再次保存，预览内再次保存为 Skill/导出。步骤数量在列表、详情摘要、Tab 和图谱面板等位置重复。

建议：统一对象操作栏。步骤编辑只保留字段及步骤操作；预览仅保留复制；数量在当前对象摘要保留一次，选择列表中可保留帮助辨认的数量。图谱正文不再增加“可编辑流程图”标题和重复数量。没有修改时保存操作保持低强调，不能呈现醒目的蓝色禁用按钮。

验收：同一工作流当前视图只有一处保存、导出入口；减少至少一层图谱头部，图谱工具条直接服务画布。

### P1：捕获空态重复引导

`App.tsx:2977` 与 `3111` 起：顶部和中央各有开始按钮、各有说明；中央还有图标、标题、三张步骤卡。空态比业务内容更复杂，并显示没有决策价值的当前应用标识。

建议：未开始时只保留一个简短空态、一句范围说明、一个“开始捕获”按钮。操作步骤改为一行辅助说明；开始后显示状态、停止操作和事件列表。隐私范围说明保留一次，实际异常仍明确显示。

验收：空态只有一个开始入口、一份说明，不出现三块装饰性步骤卡和无用应用标识。

### P1：账号卡片固定高度、状态叠加

`apps/desktop/src/accounts.css:787` 固定 `height:320px`，`:925` 的配额区再加同色边框卡片；一条配额也撑出大块空白。实机同时出现“当前配置”、卡片“当前账号”、绿色整卡边框和底部“当前使用中”，多次表达同一状态。

建议：保留原有卡片网格，卡片随配额内容自然增高；去掉配额区内层卡片。当前账号保留一处清晰文字标记，取消整卡高亮边框和重复身份条（身份不属于任何保存卡片时仍须显示）。正常、套餐、更新时间使用一行安静元信息；过期、受限和恢复入口继续显式展示。安全/会话说明集中成一个简短区域，完整含义保持可读。

验收：单条配额没有大块填充空白；卡片只有一层边界；同一账号的当前状态只强调一次；刷新全部仍在添加账号左侧。

### P1：MCP 重复身份挤占配置

`apps/desktop/src/components/McpThreeColumn.tsx:875` 起：名称、传输、目标数、启用态、中央 ID；随后常驻重启提示、配置标题中的 ID、禁用名称输入及不可改名说明。用户到达可编辑参数前需要跨过多层同类信息。

建议：头部保留名称和一行必要状态；名称/ID只呈现一次，不用禁用输入重复标题。保持参数配置优先；分发数量放在折叠的分发入口；重启生效提示靠近保存结果或配置说明。删除移入可发现且键盘可达的更多菜单，保留确认流程。

验收：命令/URL等实际配置紧接对象头部；不再出现三份相同 ID；默认详情不展开整张分发矩阵。

### P2：环境列表在窄栏过早纵向堆叠

`App.tsx:2255`、`:2406` 以及 `app.css` 的 `@container(max-width:600px)`：已经去掉嵌套卡片，但当前约549px详情宽度下，每行都拆成名称、说明、操作，多行截断的描述几乎不能帮助区分，按钮却占独立整行。

建议：环境列表在可容纳时保持“名称/简短说明 + 右侧动作”一行结构，按实际内容容量换行，不能套用统一600px规则将所有列表都变成长表单。说明仅在有区分价值时呈现；挂载状态和动作合并表达，保留触屏/键盘可操作性。

验收：在当前窗口中不强制所有动作另占一行；首屏可浏览更多 Skill；全局和项目模式采用同一行结构。

## 收敛标准

1. 同一对象的一项信息只在当前任务区主要表达一次；导航列表中的辨识信息按需保留。
2. 同一操作不在头部、面板和底部重复陈列。必要的主操作最多一处强强调，辅助操作用中性样式。
3. 主内容一层容器；账号仍可用卡片区分账号，但配额不能再套一层同类卡片。
4. 面板高度跟随内容。文档、编辑器、画布的工作空间可以扩展；状态摘要和单条配额不得用固定高度填空。
5. 正常/就绪用安静文本；错误、过期、需要用户处理的状态清晰可见。不能只靠颜色表达。
6. 说明只保留会影响理解或决策的信息，删除“液态玻璃”“微晶排版”等实现/装饰话术。
7. 无输入outline、无可见滚动条继续保持；不能删标签、键盘焦点、可访问路径和安全确认来减少界面元素。
8. 当前窗口优先通过：业务详情约549px时不逐项强制纵向堆叠；更窄时按具体组件容量折行。

## 静态检测的交叉验证

本轮运行 `detect.mjs --json apps/desktop/src`，返回10条：5条布局属性动画、5条弹性缓动提示。后5条属于命名误报：`app.css:7` 的 `--motion-spring` 实际是 `cubic-bezier(0.2,0,0,1)`，不能据变量名断言有弹跳。其余5条为宽度/padding动画候选，其中进度条宽度动画有明确状态反馈目的，不能一概删除；项目规则成功状态改变padding属于应进一步简化的候选。

扫描没有覆盖重复文案、重复操作和固定高度造成的视觉负担，因此不能用扫描数量或构建通过证明极简合格。此次未运行性能/对比度测量，不宣称相关指标不达标。无检测覆盖层注入、无新建临时服务；检测JSON只保存在临时目录。
